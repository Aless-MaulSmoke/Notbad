Este documento substitui o conteúdo anterior e registra as decisões tomadas
para a evolução do Notbad, além do plano de implementação em fases.

CONTEXTO

Esta pasta é uma recompilação do Windows Notepad chamada Notbad. O Ghidra
gerou a recompilação e o C bruto; o opencode produziu a versão 1.0 em C++
com o toolset v141 (Visual Studio 2017). Agora iniciamos a versão 1.0.1,
mantendo o visual minimalista do
Notepad original e adicionando recursos de mini editor de código.

PRINCÍPIOS DE INTERFACE

- Sem barra de botões (toolbar). A interface continua sendo janela de
  edição, menu e barra de status.
- Todo recurso novo deve ter atalho quando fizer sentido, e o atalho deve
  aparecer no menu no padrão do notbad.rc:
  "Item do Menu\tCtrl+X" + entrada equivalente em IDR_ACCELERATOR.
- Recursos de alternância usam marca de seleção (check) no menu.
- TreeView não aparece por padrão; só é criado após "Abrir Pasta".
- Barra de abas sempre visível, mesmo com uma única aba.
- Fonte e word wrap são globais. Encoding, read-only, undo e estado de
  modificação são por documento.

ARQUITETURA DECIDIDA

- Não será usado MDI Win32 clássico. A interface será de abas com um
  controle RichEdit por documento.
- Cada documento terá: HWND do RichEdit, caminho, título, encoding,
  read-only, modified e índice da aba.
- O estado global de documento único (g_hWndEdit, g_szFilePath, g_encoding
  etc.) será substituído por uma lista de documentos e um documento ativo.
- RichEdit: Msftedit.dll / MSFTEDIT_CLASS, com fallback para RichEdit20W.
  Undo multinível nativo, limite de undo configurado e buffer limpo ao abrir.
- O editor terá subclass por documento para auto-indent,
  indentação de bloco e Tab/Shift+Tab.
- Barra de abas: SysTabControl32, com marcador "*" para documento sujo,
  botão de fechar em cada aba e reordenação por arrastar/soltar.
- Layout: status bar embaixo; abas no topo; TreeView opcional à esquerda;
  gutter de números e RichEdit ativo à direita.
- Título da janela e status bar refletem sempre a aba ativa.
- Aba inicial: sempre "Untitled" em startup normal.
- Nunca restaurar sessão de abas.
- Arquivo via linha de comando/Explorer substitui a aba inicial, sem criar
  uma aba vazia extra. Se falhar ao abrir, permanece "Untitled".
- Drag-drop: sempre abre nova aba, mesmo se o arquivo já estiver aberto.
- TreeView: abre arquivo em nova aba; se já aberto, apenas dá foco à aba.
- Fechar a última aba encerra o aplicativo, com prompt de salvamento.
- Salvar (Ctrl+S) salva apenas a aba atual.
- Salvar tudo (Ctrl+Alt+S) salva todas as abas abertas.
- Sem histórico de clipboard. O requisito é undo multinível (vários Ctrl+Z).
- Find/Replace: diálogo próprio modeless do Notbad, com opção de escopo
  "todos os arquivos abertos" e opção "Case sensitive".
- Numeração de linhas opcional no menu View, com números lógicos (linhas
  quebradas por word wrap não recebem número extra).
- Conversor Tabs <-> Espaços e largura de tab ficam no diálogo
  "Indentation..."; atuam na aba ativa.
- Nenhuma alteração no visual além do necessário para abas, TreeView
  opcional e gutter opcional.

FASE 1 — MODELO MULTI-DOCUMENTO, RICHEDIT E ABAS
Objetivo: substituir o documento único por múltiplos documentos com abas.

1.1 Criar struct Document e lista de documentos.

1.4 Migrar operações de New/Open/Save/Save As para o documento ativo.
1.5 Criar SysTabControl32 sempre visível e sincronizar TCN_SELCHANGE.
1.6 Implementar layout: status, abas, área do editor.
1.7 Atualizar título, status bar e estado de menu por aba ativa.
1.8 Implementar fechamento de aba com prompt de salvamento.
1.9 Manter encoding, read-only e modified por documento.
1.10 Aplicar fonte global a todos os RichEdits.
1.11 Preservar undo multinível por aba.

Critérios de aceite da Fase 1:

- Fechar aba suja pergunta se deseja salvar.

- Fonte global aplicada a todas as abas.

DECISÕES ASSUMIDAS

- Word wrap global, como no Notepad atual.
- Fechar a última aba encerra o aplicativo.
- "Abrir..." cria nova aba; TreeView foca aba existente.
- Duplo clique no TreeView abre arquivo.
- Largura de tab configurável.
- Números de linha lógicos.
- Link do About permanece texto estático; pode virar SysLink depois.
- Sem restauração de sessão de abas.

RISCOS

- Gutter de números com word wrap e scroll é o ponto mais delicado.
- Diálogo de Find próprio substitui o visual nativo do Windows.
- RichEdit pode exigir ajustes de comportamento de line endings e tab stops.
- Muitos arquivos e comandos serão reorganizados; testar regressões de
  impressão, encoding, read-only, Go To e configurações.

- TreeView: atalho alterado para Ctrl+T; o conteúdo é relido do disco ao

  preservando pastas expandidas e item selecionado.
